## 项目边界

Social Trend Creative 是独立调度和创作服务。它拥有自己的管理页、计划任务、来源池、SQLite 数据库和图片目录；TrendRadar 负责原生 RSS 来源采集，Gemini2API 负责事件注释、图案提取和提示词生成，Flow2API 只负责生图。

## 核心运行规则

- 总架构为“外媒原生 RSS → TrendRadar → 来源条目池 → 同事件热点聚类 → AI 提取视觉方向 → 全量方向形成双提示词 → 随机生成独立图案 → 参考图生成产品图”；Flow 不得直接消费来源条目或原始热点。
- 热点、视觉方向和提示词三池共享同一个流水线轮次且不随机抽样；手动“获取热点”依次建立三池，独立图案阶段才随机抽取，产品图消费实际图案资产。
- 热点获取和两步生图使用独立分钟间隔：前三池默认 165 分钟，图案→产品默认 90 分钟；两个自动开关默认关闭。
- 热点获取覆盖查询窗口内的全部来源条目；`candidate_count` 只控制 AI 批处理大小，不限制最终热点数量。
- 第一阶段只如实保存高层事实、可选来源和风险标记；品牌、版权对象、公众人物、政治或敏感热点不会仅因类别被遗漏。
- 第二阶段可从一个原始热点提取零个、一个或多个安全、原创、可复用且与产品无关的视觉图案方向；无法安全原创化的热点不会进入可用图案池。
- 提示词阶段为每个尚未处理的视觉方向建立 `pattern_prompt` 和参考图产品提示词；前者允许漫画、图标、徽章、符号、抽象纹样等独立图稿形式，后者明确物品和印刷呈现。
- Flow 先输出无产品的独立图案，再通过 OpenAI 兼容 `image_url` Base64 输入把该图案用于杯子、手机壳、衣服、备胎罩等单一物品。
- 证据URL和发布时间为可选参考，不作为生图门禁；不得伪造来源。
- 不设置旧的“最终最多保留 5 条热点”门禁；同事件报道在聚类阶段合并，不安全方向只在图案提取阶段处理。
- “热点来源平台”只表示发现来源，不是图片发布渠道或目标平台。
- 管理页面打开后自动连接同源 API，不要求输入管理密钥；`5920` 端口只允许部署在可信内网。
- 密钥、Webhook和签名只从环境变量读取，不写入数据库或日志。

## 数据与部署

- SQLite：`data/trend-creative.db`
- 图片：`data/assets/<run>/<trend>/`
- 可用图案池：`trends`（为兼容旧数据库保留表名）
- 提示词池：`prompt_pool`
- 独立图案：`pattern_assets`，通过 `prompt_id` 追踪随机消费的提示词
- 产品图记录：`generations`，通过 `prompt_id` 和 `pattern_asset_id` 追踪提示词及实际参考图
- 来源条目池：`source_entries`；同步状态：`source_sync_state`
- 默认端口：`5920`
- Docker服务：`social-trend-creative`
